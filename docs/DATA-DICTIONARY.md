# 保费补退定义

每份保单有且仅有一条issue基线。change按effective、责任、version选版；同生效日同版本矛盾拒绝。cancel必须引用同保单的change，取消整份变更，不按录入顺序覆盖。区间为[start,end)。年度保费按所在自然年365或366日拆分，跨年强制切段。先求每段精确保费，再最大余额法分配到分，使段合计等于保单总额。paid为已收金额，总应收减已收为补退额，正数补缴、负数退费。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

## 结案签字

结案必须由保障、财务两名复核各自确认自己负责的当前事实，工作台只发布双方共同确认的唯一结案版本，下载复用同一签字证据。

- 保障事实：每份保单的有效责任区间及其来源批单（来源行、生效日、版本、责任），以及撤销结果。不含金额。
- 财务事实：每份保单的应收、实收、补退与分段保费。不含区间边界与来源行。
- 事实按角色分别规范化（键排序、字符串保形）后取 SHA-256；签字绑定 `(角色, 事实指纹, 规则版本)`，不绑定整批 run_id，也不绑定金额合计。
- 因此：只改金额时保障签字沿用、财务须重签；来源批单被替换但金额不变时财务签字沿用、保障须重签；备注等不影响两层事实的改动两者都沿用。这正是"按金额复用"与"一律重签"之间的裁决。
- 签字台账只增不改：同角色对同一事实重试同一意见幂等，不新增签字；对同一事实提交相反意见返回 `CONFLICT`（409），原签字仍可按签字ID取回；数据库触发器拒绝任何 UPDATE/DELETE，原始签批不会被覆盖、也就无需"恢复"。
- 两名复核的签字是彼此独立的行，并发提交互不覆盖；先写者生效，后到者若意见不同则被拒绝。
- 结案版本仅在两层事实都有"通过"签字且行数对账平衡时发布，同一 `(保障指纹, 财务指纹)` 只发布一次；发布失败不新增行，旧版本保持可下载。每次新结案以递增版本另起一行，旧版本保留在 `previous_closures`。
- 下载以已发布结案版本为唯一入口：缺失任一签字返回 `UNPUBLISHED`(409)，证据指纹不一致返回 `EVIDENCE`(409)。证据CSV内嵌两行签字证据与结案行，响应头 `X-Evidence-SHA256` 即该指纹。
